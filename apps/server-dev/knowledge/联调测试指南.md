# 联调测试指南

## 核心原则

联调测试的目标是验证整个系统端到端可用。重点检查 4 个模块的**集成接缝**。

## 测试流程

### Phase 1：环境启动
1. 数据层：数据库可连接、表结构正确
2. 后端：服务器启动、监听正确端口
3. 前端：开发服务器可访问
4. Ext：扩展可在浏览器中加载

### Phase 2：接口连通性
1. 前端 → 后端：验证 API 调用（≥3 个核心端点）
2. 后端 → 数据层：验证数据库读写
3. Ext → 后端：验证扩展 API 调用
4. 前端 ↔ Ext：验证消息通信

### Phase 3：功能流程
1. 执行需求确认报告中的核心用户流程
2. 浏览器操作验证（打开、点击、填写）
3. Ext 核心功能（弹出窗、内容注入）

### Phase 4：异常场景
1. 网络中断行为
2. 认证过期处理

## 浏览器测试方法

使用 browser-use MCP 或浏览器 Agent 工具操作。前端验证通过页面交互，Ext 验证通过加载扩展并触发功能。

## verdict 判定规则

> verdict 规则由 skill.md 的 verdict 语义表定义，此处不重复。

### ✅ 正例：核心流程通过
- 前端页面可访问 + 后端 API 返回 200 + Ext 成功调用 API（全部通过）

### ❌ 反例：CORS 阻断
- 前端调用后端 API 时浏览器报 CORS 错误 → severity: high，模块：后端
